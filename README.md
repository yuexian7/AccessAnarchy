# Access Anarchy（出入口无碰撞）

> 游戏内模组名会按语言显示本地化版本（中文＝出入口无碰撞，12 语对照见 `开发笔记.md` §⑥）；Paradox Mods 上的显示名始终是 `Access Anarchy`——发布接口只有一个 `displayName`，无法按语言切换。

**都市：天际线 II (Cities: Skylines II) 代码模组 · 适配游戏版本 1.6.0f1 · 零 Harmony 补丁**

让车辆在通过停车场、仓库、商场等建筑物的出入口时不再因行人减速停车，直接穿过行人；行人的行走行为、车辆之间的避让完全不受影响。

## 它解决什么问题

原版游戏中，建筑出入口（停车场匝道、商场/仓库的连接道、停车楼坡道）是车辆与行人冲突的高发点：只要有行人横穿，车辆就会排队等待甚至堵死整个出入口。本模组按照 Anarchy 系列模组的设计哲学（"优先 ECS 数据编辑而非 Harmony 补丁"），通过编辑共享 ECS 数据实现该行为。

## 工作原理（一句话版）

游戏里车辆避让行人的唯一动态机制，是车辆读取自己车道的 `LaneOverlap`（车道重叠关系）缓冲，看到重叠的行人道上有行人登记就刹车。本模组用一个 ECS 系统**持续删除"出入口车道 ↔ 行人道"的重叠条目**——车辆看不到行人道，自然不再减速。行人自己根本不读这份数据，所以行人行为不变；车辆之间的重叠条目原样保留，所以车-车避让不变。

没有 Harmony 补丁、没有系统替换、没有改动任何游戏方法。

## 设置

模组选项页（主菜单或游戏内 → 选项 → 模组 → Access Anarchy）：

| 选项 | 默认 | 说明 |
|---|---|---|
| 车辆穿过行人 | 开 | 总开关。关闭后会触发一次全城车道重叠关系重建，完全恢复原版行为（关闭瞬间会短促卡顿，属正常） |
| 取消避让范围 | 仅出入口区域 | `仅出入口区域` 或 `全部道路（全局）`。仅出入口区域＝建筑出入口、车库坡道、停车场与建筑内部道路这一整片；全局模式会禁用全市所有车让人行为，含人行横道（有信号灯的路口仍会因红灯停车，那是原版信号灯逻辑，不是让行人） |

「自定义标记」板块（**v0.8.3 只是占位，三条全部标灰不可点，功能在 v0.9.0 实现**）：计划提供「建筑和设施」「人行横道」「路口」三项，开启后点击对应对象即可把它设为无碰撞模式，且不受总开关与「取消避让范围」的限制。

范围就这两个开关，v0.8.2 及以前的「出入口区域选择」三条勾选项已合并进「取消避让范围 · 仅出入口区域」：停车场、建筑与外部道路的车辆出入口、建筑内部道路现在同开同关。三轮实机证明这三类在数据上分不开（停车场大门与商店大门是同一种 `ConnectionLane`），而"紧邻出入口"这条兜底天生跨类，留着只会让玩家看到互相覆盖。合并后**人行横道照常避让**：出入口模式下指向人行横道的重叠条目一条都不删。

v0.8.5 起「仅出入口区域」的覆盖面补上了一类漏判：仓库、商超那种**货运/装卸口**连道（原版只给它 `Inside|AllowCargo`，不带 `Road|Track|Parking`），此前只有全局模式覆盖得到，两种模式对"哪些是车行道"给出相反答案，表现就是"部分建筑生效、部分不生效"。

切换范围后范围变窄的那部分不会自己回来，模组会请游戏重建一次车道重叠关系再按新范围重删，所以会有一次短暂卡顿，属正常。**请勿在游戏中短时间内频繁修改设置**，连续切换容易让某一轮重建没落地就看到混乱结果。

快捷键（在选项页「快捷键设置」板块里，位于「自定义标记」下面；可改键、可清空，改键会持久化）：

| 快捷键（出厂默认未绑定） | 作用 |
|---|---|
| 开启/关闭本模组 | 总开关的快捷键 |
| 切换取消避让范围 | 在「仅出入口区域」与「全部道路（全局）」之间切换 |

首次订阅时这两行都是空的，需要玩家自己按一个键；设过之后重启游戏会照玩家存的走，不用
再管。给玩家推荐几个原版没占的裸键：h / j / k / n、F6、F7、F8、F10-F12、数字 4-0。

⚠ 别把这两个键设成原版已占用的裸键（R/T 是相机缩放与旋转、F/G/Q/E、X/Z/B/M/L、空格、PageUp/PageDown 等都在原版表里）：游戏会弹「快捷键重复」提示，并且**在冲突期间直接把模组的热键动作禁用掉**，局内按了没反应。判据与完整按键表见 `开发笔记.md` §⑤。

用快捷键切换时可能卡顿一下：避让范围变小或关闭模组时，需要请游戏重建一次全市的车道重叠关系（与读档时的重建同一条路径），属正常现象。

**模组快捷键优先**：本模组的快捷键优先响应，建议不要与其它模组使用同一组键，否则对侧模组可能收不到那次按键。

设置自动保存，改动即时生效，无需重启游戏。

⚠ **道路限速不要设得太高**：如果道路限速设置过高，车辆AI系统会崩溃失效。本模组只是取消车辆对行人的避让，不承担车辆 AI 本身的行为上限。

## 兼容性

- **零 Harmony 补丁**——不存在补丁被其他模组 `UnpatchAll` 拆掉的问题，也不与任何基于 Harmony 的模组（Traffic、Skyve 等）产生补丁冲突。
- 与修改交通行为的模组理论上可共存：本模组不持有任何游戏侧缓存，删除只在修路/建拆触发游戏重建后重新应用（事件驱动），别的模组怎么改车道数据都不会导致永久性不一致；关闭或缩小避让范围时会请游戏重建全市重叠关系，不会留下残留状态。
- Realistic Path Finding 等改行人寻路的模组不受影响：行人寻路不读取本模组删除的 `LaneOverlap` 数据。
- v0.8.4 起本模组**不再改动行人车道自己**的重叠数据（人行道、人行横道、建筑的人行大门道）。原版唯一读那份数据的地方是红绿灯划分行人相位（`TrafficLightInitializationSystem.cs:515-530`），以前的判定把行人设施误认成"车辆出入口"，可能连带影响信号灯分组；现在这类实体一律出局。

## 卸载安全（长期约束，每个新功能都要过这条）

取消订阅、直接删掉模组文件夹、或在模组管理器里关闭本模组之后，下次进入游戏**不需要**本模组在场也不会出问题：出入口避让自动恢复原版，日志里也不会出现与本模组有关的报错。这不是"理论上安全"，而是三条机制共同保证的：

1. **不往存档里写任何模组自有数据**。本模组没有声明任何组件类型，对世界数据的改动只有两类：改车辆车道 `LaneOverlap` 缓冲里的条目（且只改游戏已有该缓冲的实体，从不新增缓冲），以及临时给实体加原版自己的 `Updated` 脏标记。后者由原版 `CleanUpSystem` 在每帧 Cleanup 阶段移除，与模组是否存在无关。
2. **游戏每次进入地图都会全量重建重叠关系**。原版 `LaneOverlapSystem.OnGameLoaded` 把 `m_Loaded` 置位（`Net/LaneOverlapSystem.cs:1899-1902`），下一次 `OnUpdate` 即改用"全部 owner / 全部车道"查询并把 `m_UpdateAll` 打开（`:1917-1919`、`:1954`），逐条车道 `bufferData.Clear()` 后重算（`:1077`）。这条路径在**每次进图**时都会走（不只是读档），所以模组不在场时，被删掉的行人条目必然由游戏自己补回来。
3. **模组消失后没有任何东西需要被解析**。不打 Harmony 补丁；不注册游戏会按名字/类型回查的持久对象；热键走 `ModSetting` 自己的输入映射，不会进游戏的键位设置文件；设置与键位只存在模组自己的 `AccessAnarchy.coc` 里，而游戏读的是硬编码列表、不扫描该目录——模组没了，这个文件就只是被忽略。

配套的两处防御（v0.8.5）：`OnDispose` 里注销选项页那一句现在包在 try/catch 里（它抛出会让 `Setting.Instance` 清不掉、并在 Player.log 留下一条属于本模组的卸载错误）；键位诊断在 `InputManager.instance` 已为 null 的关机序列里直接跳过。

## 性能

本模组是纯 ECS 数据编辑，不hook任何方法调用，稳态开销来自下面四件事：

1. **出入口区域的重建**。模组要把"车辆出入口 + 其附近路段"的车道挑出来，删除它们指向行人道的重叠条目。v0.8.4 起这件事**只在有变化时发生**：车道数量变了（施工/建拆）、或原版自己重算过某批车道的重叠关系；v0.8.5 起"原版重算过"是**即时**起轮信号（上一轮跑完后至少隔 256 模拟步再起，约 1× 速度 2 秒），不再等下一个 512 步检查点。一张图放着不动时，只有每 8192 步一次的长兜底。以前是每 2048 步无条件全量重建一遍，大城市里那基本是白烧一条 worker 线程——玩家反馈的"帧数正常但模拟变慢"就是它。
2. **锚点范围**。"仅出入口区域"除了出入口车道本身，还包括紧邻出入口的路段（32 米）。v0.8.4 起锚点只从**车行车道**采集；此前人行道、人行横道、建筑的人行大门道也被当成出入口，在一位作者的实测存档里让锚点来源从 4.8 千条虚增到 11.1 万条，覆盖车道从停车场周围扩到全城 51% 的车道，扫描量随之放大一个量级。
3. **每帧的跟随检查**。原版在修路建拆时会重算重叠关系，模组要跟上去重删。这一步按原版同一个闸门取实体，正常游玩时匹配到的数量与原版自己做这件事相同，不会额外放大。
4. **空转的固定税（v0.8.5）**。原来每个模拟步都要向游戏申请一次命令缓冲、排一个查询必然为空的跟随 job、再把自己登记成 barrier 的生产者。单次只有几微秒，但乘上每渲染帧的 1–8 个模拟步就是长期白付；现在这一步开头先判"到底有没有活"，没活直接返回，什么都不申请。

如果你在启用模组后仍感到明显掉帧或模拟变慢，请带 `...\Cities Skylines II\Logs\AccessAnarchy.AccessAnarchyMod.log` 里这几行来反馈：`Access Anarchy v… loading`、`Anchor grid: … vehicle source lane(s) -> …`、`Access-zone rebuild driver: … round(s) started, … check(s) skipped`、`Access set audit: …`。它们能直接说明模组在做多少工作，而不需要靠猜。
